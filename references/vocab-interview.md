# 词表访谈：在动手之前把概念定下来

LLM 写出来的屎山，最常见的一种是**概念碎片**：每次会话都没有记忆，同一个东西这次叫 `user`，下次叫 `account`，再下次叫 `member`。每份代码单看都没问题，合在一起就是三套说法。文件级的去重查不出这个，只能靠一份**归你所有**的词表。

在本 skill 的适用范围内（多个 agent 写同一个仓库，见 `SKILL.md` 的 Scope），`vocab.json` 是**开工前提**，跟受保护的远端一样：没有就先做这一步，不往下走。几个 agent 各开各的会话、各起各的名字，正是概念碎片的主要来源。

这一步排在 Phase 0（采集事实）之后、Phase 1（打分）之前。已有词表的仓库跳过访谈，直接看审计报告第 9 节。不在适用范围、只想统一命名的项目，也可以单独用这一节。

## 1. 分工

- **你定概念**：有哪些核心概念、每个是什么、**不是什么**、旧名字退役了没有。这是判据，归你。
- **agent 定代码**：按词表起名、写实现、写测试。
- **名字可以商量，边界不能**：正式名优先选 LLM 最顺手的叫法，其他叫法放进 `alt_labels`，这样它照习惯写也能被映射回来；但「是什么、不是什么」只能你说了算。

## 2. 访谈问题（agent 照着问，你来答）

一次只问一个概念。**首批收五个左右就能开工**，不求一次做全：先挑审计第 9 节已经报出「近义分叉嫌疑」的概念（碎片已经出现，最该先定），不够再补最核心、最容易被叫乱的。以后第 9 节冒出新的分叉，再按同样的问法补一个，版本号走小版本。

1. 这个项目里最核心的几个「东西」是什么？（先列名字，不展开）
2. 对每一个：
   - 一句话说它**是什么**。
   - 它**不是什么**？最容易和哪个概念混？两者的区别是什么？
   - 大家（包括你自己、文档、老代码）还会用哪些别的叫法？
   - 代码里你希望用哪个名字当正式名？没有偏好就用 LLM 最顺手的那个。
3. 有没有已经不用、但老代码里还残留的旧名字？改成了什么？

agent 在访谈里只负责问和记，**不替你回答**，也不拿代码里现有的叫法当默认值往里填。答不上来的概念先不进词表，宁缺毋滥。

## 3. 生成什么

按 `assets/templates/vocab.json` 生成仓库根目录下的 `vocab.json`：

- `version` 从 `0.1.0` 开始，用语义化版本号。加概念、加别名算小版本；改定义、改边界、退役概念算大版本。
- `approved` 一律先写 `false`，你逐条看过再改成 `true`。
- 每条「不是什么」顺手起草一条**反面断言测试**，同样标「待你批准」。例子：`not` 里写了「user 不是 organization」，就起草一条测试，断言 `User` 类型不能直接当 `Organization` 用（具体写法按项目语言来）。
- 退役的名字进 `retired`，**退役 id 永不复用**，以后哪怕想起同一个名字，也换一个新的 id。

## 4. 放在哪、谁能改

- 只有一份：仓库根的 `vocab.json`，或者在 `.agent-ready.json` 里用 `"vocab": "<路径>"` 指定。规则文件、`AGENTS.md`、`STRUCTURE.md` 都只写指针，不抄内容。
- `vocab.json` 属于判据层，和闸门、红样本、规则文件一样：进 CODEOWNERS，agent 只能写进 `proposals/` 提议，不能自己合并。

## 5. 审计怎么查（`audit-workspace.py` 第 9 节）

只看公共符号（Python 顶层和类里不以 `_` 开头的 `def` / `class`；JS/TS 的 `export`；Go 首字母大写；Rust 的 `pub`；Java/Kotlin/C#/Swift 的 `public` 类型），私有变量随便起名，不算碎片。

| 有词表时会报 | 含义 |
| --- | --- |
| 代码用了别名而不是正式名 | 碎片已经出现，改名或在 PR 里说明 |
| 已退役的 id 还在用 | 迁移没做完 |
| 同一别名挂在两个概念上 / 别名撞上别人的正式名 / 退役 id 被复用 | 词表自身矛盾，找你裁决 |
| 概念缺「不是什么」或定义还是占位 | 边界没定 |

没有词表时，第 9 节会报「开工前提缺失」，并把近义分叉嫌疑列出来，当作首批访谈的候选。

词表没管到的部分，脚本用一组内置近义词（`user/account/member/customer`、`config/setting/option/preference`、`message/msg` 等）报**嫌疑**，只是提示，不算结论。项目可以在 `.agent-ready.json` 里加 `concept_synonyms`（追加组，例如 `[["ticket", "issue", "case"]]`）或 `concept_ignore`（按组内第一个词屏蔽整组，例如 `["order"]`）。屏蔽是放宽：被屏蔽了几组会写进报告和 JSON 的 `signals`，`.agent-ready.json` 本身也属于判据，改它要你批。

解析失败的代码文件单独计数，并断言「枚举数 = 解析成功 + 解析失败 + 不支持的后缀」，不静默跳过。

体检模式下再跑一次，新冒出来的别名和近义分叉就是漂移。
