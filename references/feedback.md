# 试用反馈清单（`no-self-grading`）

> **给谁**：**第一次**拿这个技能在**自己的仓库**上试的人。
> **目的**：不是打分，而是找出「**这个技能在真实仓库上哪里不灵**」——
> 尤其是**平台映射表会过期**、**9 维度里哪一维在别人的仓库上判断失真**这两类。
> **预计 10–15 分钟**。**允许留空**：「说不清 / 没试」本身就是有用的信号，比编一个答案强。
> **回信请贴全文，不要只贴结论** —— 上下文比结论值钱。

---

## 0. 先跑一遍（3 步，约 5 分钟）

1. 把技能目录放到你的 skills 目录下：`<skills>/no-self-grading/`。
2. 在你**想审计的仓库根目录**执行下面两条（`<skills>` 换成实际路径）：

```
python <skills>/no-self-grading/scripts/audit-workspace.py --root .    # 事实采集（只读）
python <skills>/no-self-grading/scripts/verify-refs.py  --root .       # 引用一致性自检（只读）
```

3. 把这两条命令的**完整输出**贴回给我。

> ⚠️ 两条都是**只读**的，不会改你的任何文件。
> ⚠️ 若 `verify-refs.py` **退出码 = 2**，那是它**拒绝给结论**（说明它认为扫描范围不可信）——
> **不是 bug**。把它的提示原文一起贴来，这正是我想看的反馈之一。
> ⚠️ 两条都必须**从仓库根跑**（脚本自己也会检查这一点）。

---

## 1. 基本情况（4 问）

1. 仓库规模：文件数大约多少 / 主要语言 / 是不是 monorepo？
2. 你是**一个人**在做，还是**多人 / 多 agent** 并行？
3. 你平时用哪个 AI 工具（CodeBuddy / Claude Code / Cursor / Copilot / 其他）？
4. 你**本来想解决什么**？（一句话就够）

## 2. 技能的实际表现（6 问 —— **这一节最重要**）

5. **哪几个维度对你有用**？（9 维度：入口机制 / 单一事实源 / 分工与写权限 / 状态与交接 /
   引用一致性 / 版本控制 / 记忆持久化 / 敏感数据卫生 / 规范自洽性）
6. **哪一维在你的仓库上"打不准"**？（例：它说「缺入口文档」，其实你有，只是叫别的名字）
7. 有没有它给了 **0 分或 1 分、你觉得不该扣**的？反过来——它给了 **2 分但你心里知道那儿是烂的**？
8. 你**实际动手修了哪几项**？修完有没有**再跑一遍**自检（`ERROR` 是否降到 0）？
9. ⭐ **平台映射表**（`references/platform-mapping.md`）里，**你用的那个工具**的落点是**对还是错**？
   （这条最值钱：那张表是**证据驱动**的，带调查日期，**会过期**。）
10. ⭐ `traps.md`（踩坑清单）里有没有哪条让你「**啊，我也踩过**」？是哪一条？

## 3. 触发与体验（3 问）

11. 你是怎么让 agent 用上这个技能的？**它自己找到的**，还是你手动指路？
12. 技能的 description 有没有让你**误以为**它管别的事（或漏用了它）？
13. 你会在**下一个新仓库**上再用它吗？不会再用的原因是什么？

## 4. 自由发挥（随便写）

16. 有没有**该有而没有的维度**？（你现在靠什么补上？）
