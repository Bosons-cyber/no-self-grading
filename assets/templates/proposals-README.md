# proposals/ —— 卡住时的出口

> 放到目标仓库的 `proposals/README.md`。

agent 被闸门挡住、又认为闸门本身有问题时，**不要改闸门，不要加豁免，不要绕过**。按下面做：

1. **停下**，在输出最后一行打出：

   ```
   ###BLOCKED reason=<一句话原因> at=<闸门 id 或 文件:行号>
   ```

2. 在本目录写一份提案：`proposals/<YYYY-MM-DD>-<短名>.md`，内容：
   - **卡在哪**：哪道闸门（`GATES.md` 的 id）、完整报错、复现命令
   - **我认为的原因**：闸门误报？需求变了？还是我的实现确实有问题？
   - **我建议怎么改**：改闸门 / 加豁免 / 改范围 / 改需求，附具体 diff
   - **这算不算放宽**：如果改完会让任何红样本由红转绿，明说
3. 提交提案（只提交 `proposals/` 下的文件），等用户裁决。等待期间可以做别的不受影响的任务。

**以下改动只能走提案，agent 不能自己批**：

- 增加豁免标记（`refs:skip-*`）或 `.agent-ready.json` 里的 `skip_dirs` / `skip_prefixes` / `ignore_refs`
- 缩小自检扫描范围（`scan`）
- 修改、停用、删除任何闸门或红样本
- 把目录移出 `STRUCTURE.md` §2 的只读清单
- 修改 `CODEOWNERS`、CI workflow

**为什么这样设计**：卡住是正常的，自己放宽裁判不正常。给一个体面的出口，比每次撞闸门、再偷偷把闸门改松要高效，也让每一次放宽都有据可查。
