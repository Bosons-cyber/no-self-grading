| 目录 | 职责 | 写权限 | 备注 |

| `<<事实源>>/` | 共享事实 | 仅「事实源维护者」 | 其余只读；改动需广播 |
| `<<知识库>>/` | 资料 / 论文 | 仅「知识库维护者」 | 只增不改、只读不删 |
| `<<冻结快照>>/` | 历史报告 | **只读** | 落成后不再改，要改则新起一版 |
| `<方向容器>/<dir>/` | 各方向工作区 | **仅该方向的 agent** | 互不写对方 |
| `<<产出>>/` | 证据归档 | 各 agent 追加 | 命名带方向前缀，不覆盖 |

| `scratch/` | 一次性代码 / 试验 | 各 agent 随意 | 不审、不测；**正式代码不得 import / 引用 scratch/**（由自检拦截）；不入交付 |

## 3. 多 agent 分工约定

1. **一个方向 = 一个目录 = 一个 agent**；不碰别人的目录。
2. **共享事实源只读**：一律引用，**禁止在自己目录里复制一份**。
3. **产出统一落 `<产出>/`**，命名带方向前缀，便于跨方向对账。
4. **新方向**：建 `<name>/`，先写 `README.md`（方向 / 目标 / **判据**），再动手。
5. **引用外部依赖**：统一相对路径，**禁止绝对路径**（产物会带着它流传，仓库一改就全失效）。
6. **方向索引与状态分离**：`<容器>/README.md` 是索引；实时状态写**各自的** `STATE.md`，
   **只由该方向写**（避免并发写同一文件）。
7. **开工前先查占用**：读索引 + 目标 `STATE.md`；**同方向不要两个人同时写**。
8. **收尾要留痕**：结论写进自己的 `README.md`（**负结果也要写透**）、更新 `STATE.md`、
   跑一次引用自检、提交。

## 6. 执行规则

1. **新工作一律进新结构**，不再往旧目录加东西。
2. **不删旧目录**：迁移完成后保留一个 README 指针。
3. **改动即提交**：仓库在父目录；`git add -A && git commit`，提交信息写清「改了什么 / 为什么」。
   **新增「生成物 / 凭据 / 外来只读」目录时必须同步登记 `.gitignore`。**
4. **文档随产物同步**：新增文件或目录时，**同一轮内**更新对应索引文档（对照表见下）。
5. **改完跑自检**：`python <<scripts/verify-refs.py>>`，要求 `ERROR = 0`。

### 「新增物 → 必须更新的文档」对照表

| 新增物 | 必须同步更新的文档 |
|---|---|
| 新方向目录 | `STATUS.md` + 本文件 §1/§3 + 方向索引 |
| 新增文档类文件 | 所在目录的索引 / README |
| 新增证据 | 该方向的 `README.md` + `STATUS.md` |
| **任何结构变动** | **本文件**（唯一结构规范） |

**优先级**：本文件（结构）> `STATUS.md`（状态）> 各方向 `README.md`（细节）。
