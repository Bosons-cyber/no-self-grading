# <<容器名>>/ —— 方向索引

> 多 agent 工作区：**一个方向 = 一个目录 = 一个 agent**。
> 本文件只做**索引**：有哪些方向、谁在写、进展到哪、入口在哪。
> 各方向的**实时状态**写在各自目录的 `STATE.md`，**只由该方向自己维护**（避免并发写冲突）。

---

## 方向一览

| 方向 | 目录 | 状态 | 一句话结论 | 入口 |
|---|---|---|---|---|
| <<方向 A>> | `<<dir-a>>/` | ✅ done | <<结论>> | `<<dir-a>>/README.md`（全记录）、`SUMMARY.md`（摘要）、`RUNBOOK.md`（怎么重跑） |
| <<方向 B>> | `<<dir-b>>/` | ⏸️ paused | <<结论>> | `<<dir-b>>/README.md` |
| <<方向 C>> | 未开 | 📋 已立项 | <<为什么值得做>> | <<参考材料路径>> |

> 状态口径：`active`（有人在写）/ `paused`（暂停，可接手）/ `done`（已收口）。

---

## 开工前必做

1. **先看有没有别人在同一方向**：看本表 + 目标 `STATE.md`。**同方向不要两个人同时写。**
2. 建 `<<dir>>/`，先写 `README.md`：方向 / 目标 / **判据**。
   > 判据没想清楚就不要动手。
3. 建 `STATE.md`（从已有方向复制改）：本次做到哪 / 下一步 / 阻塞 / 上次作业 ID。
4. 查事实源确认口径；查背景资料找理论依据。
5. 产出落 `<<产出目录>>/`（命名见 `STRUCTURE.md` §4）。
6. **更新本文件的「方向一览」表**，并在 `STATUS.md` 登记。

## 收尾时必做

- 结论写进自己方向的 `README.md`（**负结果也要写透**——最有价值的产出常常是负结果）。
- 更新自己的 `STATE.md`（status → `done`/`paused`，写清未做项与原因）。
- 跑一次引用自检，确认改动没弄坏别人的引用。
- 提交。
