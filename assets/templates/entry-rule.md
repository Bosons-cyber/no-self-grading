# 始终生效的入口规则（跨平台模板）

> 「**一个始终生效的规则文件**」是个**概念**，各平台的落地形式不同。
> 下面给三种常见形态，**按目标平台挑一种**（对应关系见技能的 `references/platform-mapping.md`）。
>
> ⚠️ 这类文件通常在**会话开始时**加载 —— **改动后需新开会话才生效**，务必在文件里写明。

---

## 形态 A · frontmatter 型（Cursor `.cursor/rules/*.mdc`、CodeBuddy `.codebuddy/rules/**/RULE.mdc`）

```markdown
---
description: <<工作区名>>入口——做本工作区相关任务前必读 STATUS.md 和 STRUCTURE.md
alwaysApply: true
---

# <<工作区名>>（<<一句话定位>>）

本工作区<<做什么>>。开始任何相关任务前，**必须先读**：

1. `<<路径>>/STATUS.md` —— 项目状态（完成了什么 / 待办 / 想法）
2. `<<路径>>/STRUCTURE.md` —— 目录规范（分工 / 命名 / 写权限）

## 铁律

- 一个方向 = 一个 `<<容器>>/<name>/` 目录，互不写对方。
- 只读目录：**以 `<<路径>>/STRUCTURE.md` §2 为准**，本文件不复制清单（复制必漂移）。动手写任何目录前先查 §2。
- 产出统一落 `<<产出目录>>/`，命名带方向前缀。
- 事实源查 `<<事实源路径>>`；背景资料查 `<<知识库路径>>`。
- 新方向先在 `<<容器>>/<name>/` 写 `README.md`（方向/目标/判据）+ `STATE.md`，再动手。
- 开工前先看 `<<容器>>/README.md` 与目标 `STATE.md`，**确认没有人在做同一件事**。
- 改完跑 `<<自检命令>>`，要求 `ERROR = 0`，然后提交。
```

## 形态 B · 显式文档型（Claude Code `CLAUDE.md`、Gemini CLI `GEMINI.md`、通用 `AGENTS.md`）

无需 frontmatter，直接写入同名文件的顶部小节（平台会自动读取）：

```markdown
# <<工作区名>>

> 开始任何任务前必读：`<<路径>>/STATUS.md`（状态）、`<<路径>>/STRUCTURE.md`（规范）。

## 铁律

- 一个方向 = 一个 `<<容器>>/<name>/` 目录，互不写对方。
- 只读目录：见 `<<路径>>/STRUCTURE.md` §2（唯一出处，此处不复制）。
- 改完跑 `<<自检命令>>`，要求 `ERROR = 0`。
- 新方向先写 `README.md`（方向/目标/判据）+ `STATE.md` 再动手。
```

## 形态 C · 作用域型（GitHub Copilot `.github/instructions/*.instructions.md`）

```markdown
---
applyTo: "**"
---
# <<工作区名>> 约定

必读：`<<路径>>/STATUS.md`、`<<路径>>/STRUCTURE.md`。
铁律：（同上，逐条列出）
```

---

## 三条硬要求（与形态无关）

1. **必须指向状态与规范**：规则文件不承载细节，只负责把人送到权威文档。
2. **只读清单只有一份，在 `STRUCTURE.md` §2**：规则文件只放指针，不放副本。手抄的第二份迟早漂移，
   漂了 agent 只能猜。平台确需内联时，由脚本从 §2 生成，并由自检比对两处是否一致。
3. **写明「改动需新开会话生效」**：否则会被误判为改动无效。
