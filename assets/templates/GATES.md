# 闸门登记表（GATES.md）

> 每一道闸门（自检脚本、测试套件、hook、CI 检查……）都在这里登记一行。
> **本文件是裁判的一部分**：归用户所有（`CODEOWNERS`），agent 只能通过 `proposals/` 提改动。

| id | 闸门 | 层级 | 红线 | 有效期至 | 红样本 | 模式 | 负责人 |
|---|---|---|---|---|---|---|---|
| G1 | `<<python tools/verify-refs.py>>` 的 `###VERIFY errors=0` | 提交 | 否 | `<<YYYY-MM-DD>>` | `<<tests/red/G1-dangling-ref.md>>` | 强制 | 用户 |
| G2 | `<<契约测试命令>>` | 交付 | 是 | —（红线不过期，定期演练） | `<<tests/red/G2-*>>` | 强制 | 用户 |
| G3 | `<<新闸门>>` | 编辑 | 否 | `<<YYYY-MM-DD>>` | `<<tests/red/G3-*>>` | 影子 | 用户 |

**列的含义**：

- **层级**：编辑（写文件时就拦，如 hook）/ 提交（commit 前）/ 交付（合并或发布前）。越靠前越便宜，越靠后越权威。
- **红线**：碰了就不可接受的（凭据入库、越权目标、删除只读区）。红线闸门**不设有效期**，但要定期用合成红样本演练，确认它还会响。
- **有效期**：非红线闸门到期后要么续期（写明理由），要么删除。防止闸门只增不减，把 agent 卡死。
- **红样本**：一个**应该被这道闸门拦下**的样本，来源要独立于写这道闸门的 agent（用户写，或另一个 agent 写、用户批）。
- **模式**：影子 = 只记录不拦，用来观察误报；确认可靠后才转强制。

**治理规则**：

1. 闸门查**结果**，不查过程：在出口检查产物对不对，而不是规定 agent 每一步怎么走。
2. **关掉一道闸门，它的红样本必须报红**（运行器发现「闸门缺席」就失败）。否则闸门被悄悄拿掉也没人知道。
3. 改动任何闸门，都要拿 **main 上的红样本和 main 上的运行器**，去跑改动后的闸门。红样本和运行器都不能取自待合并的分支，
   否则改闸门的人可以顺手改掉红样本。**任何一个红样本由红转绿 = 放宽**，需要用户批准。
4. 删除闸门一律需要用户批准。
5. 红样本**只增不删**（append-only）；确需作废的，标记作废并说明原因，不删文件。
6. 新闸门先以影子模式跑一段时间，再转强制。
